Hospital file #122: 6 zero-count entries need absence explanations

Published November 13, 2026 · Source audit: 2026-10-08 05:36 EDT; full live ranged GET verification

Stored audit of one hospital price file found 6 count-zero entries without a no-remittance explanation across 48,741 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

Large files create a different review problem. A hospital cannot eyeball 13.18 million data rows, and a validator can pass structure while a tiny conditional population still needs review. This file is useful because the confirmed finding is only six entries, but the proof work had to cover the entire body.

The October 8 audit found six unique coded algorithm entries with count 0, blank allowed-amount stats, and generic notes that described OPPS APC or packaged-code payment logic. Those six sit among 48,741 coded conditional entries. The issue is missing absence explanation, not inverse encoding.

The six affected entries show why denominators matter. Six is tiny against 48,741, but the review question is not whether the file is mostly orderly. It is whether each count-zero conditional entry explains the absence of remittances where CMS asks for that explanation. In these six rows, the generic note names a payment methodology and the payer-note field is absent.

The file also shows why overlap control matters. A later candidate, R451, exactly re-verified the existing R449 finding: same URL, hash, six CSV record indices and examples. The right treatment was to enrich the existing row, not add a seventh row or a new finding. That preserved the inventory at 183 rows instead of inflating it.

The strongest contrast is the 41,187 explicit zero-final-payment explanations. Those entries may still need lookback or truth review, but they are not part of the confirmed absence-explanation gap. Keeping them out is what makes the six-entry finding defensible.

What a correction team should do

  • Pull the six exact source records and assign one owner to decide whether the missing explanation belongs in generic or payer-specific notes.
  • Do not rerun the whole 5.96 GB file just to edit six rows; use the stored record indices, then verify the full body after republication.
  • Keep the 41,187 explicit explanations out of the fix list unless a separate lookback review finds a problem.
  • Save the ETag, hash and row-width check after the next publication so the correction has a clean audit trail.

  • The original file bodies are not reproduced here. This article relies on the dated audit record, including its counts, examples and recorded provenance; it does not establish the current file state.

Treat this as a historical file dissection. Re-fetch and re-audit the current file before outreach, correction or any claim about today's endpoint state.
