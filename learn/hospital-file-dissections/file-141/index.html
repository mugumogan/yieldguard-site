Hospital file #141: 7,427 zero-count entries need absence explanations

Published November 13, 2026 · Source audit: Wednesday, October 7, 2026, 2:25 AM PDT (direct verification update cutoff)

Stored audit of one hospital price file found 7,427 count-zero entries without a no-remittance explanation across 146,604 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

The stored audit found 7,427 count-zero entries out of 146,604 applicable entries whose notes do not directly explain that no remittances existed in the applicable lookback. That is 5.066% of the applicable population.

A payment formula, fee schedule, workflow status or service label can be useful context. It does not answer the separate question CMS asks the note fields to answer: why the allowed-amount history is absent.

The review keeps explicit zero-payment explanations outside the confirmed gap. That restraint matters: the correction list should contain rows that need work, not every row with a zero count.

The dated audit record describes the file-specific pattern this way: row 143: Independent full-body retrieval, matching SHA-256 and raw JSON audit; 7,427 coded conditional zeros across seven methodology/modifier-only joint note variants; all stats absent

Read this result within its recorded scope: affected counts are row 143: 7427; applicable counts are row 143: 146604. The affected population is not a denominator for all rows in the file, and no rate is calculated where an applicable denominator was not recorded.

What a correction team should do

  • Pull the affected rows by finding row and note pattern before editing.
  • Confirm whether the zero count is true for the applicable remittance lookback.
  • Where it is true, replace formula-only or label-only notes with a direct no-remittance explanation.
  • If remittances existed, correct the count and calculate median, p10 and p90 from the same remittance set.
