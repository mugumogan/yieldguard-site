Hospital file #168: 7,565 entries pair zero counts with claim statistics

Published November 13, 2026 · Source audit: 2026-10-07 15:30 PDT; attached-source audit confirmation, not fresh endpoint check

Stored audit of one hospital price file found 7,565 entries pairing count zero with populated allowed-amount statistics across 2,055,388 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

This file is useful because the explanation fields are not standard. The hospital used custom footnotes, so the audit had to read the actual note pairs rather than assume a blank generic-note field meant no explanation.

The October 7 audit found 7,565 unique code-bearing percentage or algorithm entries with count 0 and numeric median, p10 and p90. The applicable denominator is 2,055,388 entries. Package or bundling notes do not waive inverse encoding.

The inverse finding is narrow. All 7,565 affected entries have count 0 and all three numeric stats. Other zeros have all three stats absent, so this is not a general positive-population completeness failure.

The custom footnotes matter because they describe bundling or package logic. That may help a reader understand the negotiated charge, but it does not create a remittance history. The audit kept 760,861 bundle or package semantic-hold zeros separate instead of adding them to the confirmed finding.

The metadata dates are another lesson. A file may carry last_updated_on and as_of_date fields, but those are source labels, not independent freshness proof. The article should date the audit and avoid saying the file is current today.

What a correction team should do

  • Extract the 7,565 inverse rows and identify whether the count or the statistics are stale.
  • Keep custom footnote review separate from the inverse-stat correction.
  • If count 0 is correct, blank all three stats; if the stats are correct, recalculate the count from remittances.
  • Record the metadata dates beside the audit timestamp so future readers do not confuse source labels with verification time.

Treat this as a historical file dissection. Re-fetch and re-audit the current file before outreach, correction or any claim about today's endpoint state.
