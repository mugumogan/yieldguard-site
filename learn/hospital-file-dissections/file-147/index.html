Hospital file #147: 1,365,832 entries show multiple zero-count findings

Published November 13, 2026 · Source audit: Wednesday, October 7, 2026, 3:39 AM PDT (direct verification update cutoff)

Stored audit of one hospital price file found 1,365,832 unique entries across multiple zero-count findings across 1,538,508 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

This file teaches overlap control. It has two ways to describe a problem, but counting both as separate affected populations would inflate the result. The right unit is the unique entry union.

The October 7 audit found 1,365,832 coded conditional count-zero entries with numeric median, p10 and p90. A 62-entry OPPS APC-only absence-explanation problem is a subset of that inverse population, not an additional 62 entries.

The finding starts with the union: 1,365,832 unique affected entries. Then it can explain the subset. That ordering prevents the common error of adding 1,365,832 and 62 into 1,365,894.

The inverse entries are strong because all three statistics are numeric. A first example has a percentage negotiated charge of 60 and no dollar field, which makes clear that the zero belongs to the count of allowed amounts, not the negotiated charge itself.

Most inverse entries carry explicit ZeroFinalPayments15mo notes. Those notes may explain absence, but they do not make it valid to publish claim-derived statistics when the count is zero. The 62 OPPS APC-only rows are different because they also lack the absence explanation.

What a correction team should do

  • Use one correction workstream keyed by entry ID, with two flags: inverse encoding and missing explanation.
  • Blank median, p10 and p90 on true zero-count rows; then add an absence explanation only to the 62 rows that need it.
  • If the stats are real, correct the count from the same remittance data instead of deleting statistics.
  • Report the unique union and the subset separately in any internal tracker.
