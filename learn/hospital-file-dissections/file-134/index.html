Hospital file #134: 56,510 zero-count entries need absence explanations

Published November 13, 2026 · Source audit: Wednesday, October 7, 2026, 12:08 AM PDT (direct verification update cutoff)

Stored audit of one hospital price file found 56,510 count-zero entries without a no-remittance explanation across 72,338 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

This file gives the series a phrase-level lesson. A note can sound operational and still fail to answer the compliance question. "Calculations in process" explains workflow status. It does not say there were no remittances in the required lookback.

The October 7 audit found 56,510 coded conditional zero entries with all stats blank. The generic note refers to service instances and the payer note refers to calculations in process. The applicable denominator is 72,338 coded percentage or algorithm entries.

The file has two zero populations that look similar at a glance. One population says zero instances in the lookback; the audit accepted that as an encoded absence explanation, subject to truth and duration caveats. The other says service instances and calculations in process. That second note pair does not explain the absence of remittances.

This is also not a positive-stat gap. Service instances are not paid-remittance counts, so the audit did not infer that a median should exist. The correct fix is either to encode a real absence explanation or correct the count and calculate allowed-amount statistics from remittances.

The wide-format placement caveat matters. CMS places the no-remittance explanation in payer-specific notes for wide CSV files. Here, the payer note is the field that says calculations are in process, so the gap is not just a generic-note omission.

What a correction team should do

  • Separate the 56,510 confirmed rows from the 15,828 explicitly explained zeros before editing.
  • Replace workflow-status text with a direct no-remittance explanation where the count is truly zero.
  • If calculations later produce remittances, update the count and calculate all three allowed-amount statistics.
  • Save the zero census by payer-plan group so a future template change cannot move rows between buckets unnoticed.
