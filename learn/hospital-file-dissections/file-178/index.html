Hospital file #178: 13 zero-count entries need absence explanations

Published November 13, 2026 · Source audit: 2026-10-08 04:05 EDT; full live GET body independently verified

Stored audit of one hospital price file found 13 count-zero entries without a no-remittance explanation across 68,566 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

This is the cleanest small-wide-file case in the batch. The confirmed correction list is only 13 rows, but those rows sit in a 205-column CSV with 21 payer-plan groups. The lesson is that a small fix still needs a precise map.

The October 8 audit found 13 unique code-bearing conditional zero entries with all stats blank. Generic notes are blank, algorithm fields are blank and the only payer note is a 124.75% CMS fee-schedule term. The applicable denominator is 68,566 entries.

A fee-schedule percentage tells the reader how payment would be calculated. It does not say that no remittances existed during the measured period, and it does not explain why the allowed-amount history is absent. That is the whole finding.

The file has a much larger separate population of 67,904 zero entries with past-year no-remit-payment explanations. Those rows keep lookback and truth caveats, but they are not part of the 13-row confirmed gap.

What a correction team should do

  • Pull the 13 exact source records and confirm whether count 0 is true.
  • Where it is true, replace the fee-schedule-only note with a direct no-remittance explanation.
  • If remittances existed, correct count and calculate median, p10 and p90 from the same remittance set.
  • Preserve the 205-column structure and rerun all 21 payer-plan group counts after republication.
