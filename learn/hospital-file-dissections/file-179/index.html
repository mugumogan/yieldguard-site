Hospital file #179: 1,480 zero-count entries need absence explanations

Published November 13, 2026 · Source audit: 2026-10-08 04:29 EDT; full live GET body independently verified

Stored audit of one hospital price file found 1,480 count-zero entries without a no-remittance explanation across 39,512 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

This file is a practical cleanup case. The affected population is small enough to fix, the note pattern is plain, and the file has an encoding wrinkle that makes careless editing risky.

The October 8 audit found 1,480 unique coded conditional zero entries with all stats blank. Generic notes say other, supplemental LPP notes are blank or other, and algorithm fields contain fee-schedule terms. The applicable denominator is 39,512 entries.

"Other" is not an explanation. Neither is a fee-schedule term. The affected rows need a direct statement that no remittances existed during the measured period, or a corrected count and statistics if remittances did exist.

The file has a strong comparison group. The 35,821 explicit zero-final-payment rows were excluded from the confirmed finding, subject to truth caveats. That keeps the correction list at 1,480 rather than turning every zero into a gap.

The encoding wrinkle matters operationally. The body is valid reversible CP1252, not strict UTF-8. A team that opens and saves it carelessly could change bytes while trying to fix notes. The correction workflow should preserve encoding and verify the full hash after edit.

What a correction team should do

  • Review the 1,480 affected rows by fee-schedule class.
  • Replace "other" and fee-schedule-only text with clear no-remittance language where count 0 is true.
  • Preserve CP1252 encoding and verify the full post-edit hash.
  • Keep the 35,821 explicit zero-payment rows out of the confirmed fix list.
