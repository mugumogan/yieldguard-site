What the stored audit found

This file gives the series a mature wide-CSV example. It has 63,134 rows, 552 columns and 60 schema payer-plan groups. The issue is not schema novelty; it is that formula language is being used where an absence explanation is needed.

The October 8 audit found 30,049 unique coded conditional zero entries with all stats blank and no no-remittance explanation. The applicable denominator is 2,279,846 entries. Inverse encoding is 0.

The largest confirmed class is the paid-claim-lines threshold population, with 27,910 entries. That language explains how payment behaves after a threshold. It does not say there were no remittances in the lookback.

The file is a good overlap exercise. The explicit ZeroFinalPayments15mo population is huge, but it is separate from the 30,049 confirmed gaps. Those populations must not be added.

The CP1252 note belongs in the technical appendix. It affects parsing and byte preservation, not the meaning of the absence explanation. Keeping those lanes separate makes the article more credible.

What a correction team should do

  • Export the six confirmed note classes and assign a correction owner for each class.
  • Preserve CP1252 bytes when editing; do not let a spreadsheet silently rewrite characters or column order.
  • Keep explicit zero-payment rows and semantic holds out of the confirmed fix list.
  • After republication, rerun the 552-column scope check and all six note-class counts.
