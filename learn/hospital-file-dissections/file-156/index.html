What the stored audit found

This is the file that powered the first YieldGuard research article. It is useful because the pattern is easy to explain: the count says there were no allowed amounts in the lookback, while the median field still publishes a number. The file is small enough for a reader to grasp the denominator without losing the point.

The stored audit found 1,692 coded percentage or algorithm entries with count 0 and a numeric median, out of 2,197 applicable entries. That is 77.0% of the applicable entries in this file snapshot. It is a source-bound encoding finding, not a claim that 77% of hospital files have the same issue.

The key distinction is between an explanation and a statistic. Every zero-count row in this file carries an explicit ZeroInstances15mo note, so the file does try to say why no remittances were present. CMS still says that when the count of allowed amounts is zero, the hospital should not encode the median, 10th percentile or 90th percentile allowed-amount fields. A truthful zero-instance note does not make a claim-derived median measurable.

The median-only shape matters too. The affected rows have a numeric median but blank p10 and p90. A template or calculation-path error is one hypothesis to investigate, not a cause established by this audit. The stored audit does not identify which system wrote the file, and it does not need to. The hospital owns the published file.

The clean comparison group is the 339 positive entries. They have all three allowed-amount statistics. That contrast makes the anomaly easier to test: when the count is positive, the file behaves like the CMS data model; when the count is zero, most rows still publish a median. The finding is therefore not a broad complaint about the file being unusable. It is a specific field-pair conflict.

What a correction team should do

  • Start with the affected population, not the whole file: 1,692 rows where count is 0 and median is populated.
  • Decide which field is stale or wrong: the count, the median, or the template logic that fills the median.
  • If the count is truly zero, blank the median and keep the no-instance explanation beside the row.
  • If allowed amounts existed, correct the count and recalculate median, p10 and p90 from the same remittance set.
  • After republishing, rerun the same census and save the before-and-after hash, row count and timestamp.
