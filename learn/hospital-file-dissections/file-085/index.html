Hospital file #85: 159,201 entries pair zero counts with claim statistics

Published November 13, 2026 · Source audit: Monday, October 5, 2026, 3:31:52 AM PDT

Stored audit of one hospital price file found 159,201 entries pairing count zero with populated allowed-amount statistics across 195,253 applicable entries. Historical, de-identified review; not a fresh endpoint check.

What the stored audit found

The stored audit found 159,201 affected entries out of 195,253 applicable entries where the count of allowed amounts is zero while at least one allowed-amount statistic is populated. That is 81.536% of the applicable population.

CMS treats zero as a count, not as a substitute for a measured median or percentile. A calculated price can be legitimate, but it should not be relabeled as a historical allowed-amount statistic when the remittance count is zero.

The useful review keeps the negotiated-charge fields, the count, median, 10th percentile, 90th percentile and note fields together. Fixing one field in isolation can hide the underlying conflict.

The dated audit record describes the file-specific pattern this way: row 85: Full source / same-hash audit; median populated; percentiles blank

Read this result within its recorded scope: affected counts are row 85: 159201; applicable counts are row 85: 195253. The affected population is not a denominator for all rows in the file, and no rate is calculated where an applicable denominator was not recorded.

What a correction team should do

  • Confirm whether the zero count or the populated statistic is stale.
  • For a percentage or algorithm charge requiring allowed-amount data, if no allowed amounts existed in the applicable lookback, do not encode the median or percentile fields; encode count zero and explain the absence in the notes.
  • If allowed amounts existed, correct the count and recalculate median, p10 and p90 from the same remittance population.
  • After republication, rerun the same file census and preserve the before-and-after hash, byte size, row count and timestamp.
