Hospital Price Transparency Audit Workflow

Use this workflow to organize a review of your hospital's published pricing file, record what you checked, and track corrections. It is a suggested operating process, not an additional CMS requirement or a certification of compliance.

1. Start with the published file

Record the hospital location, the page where the file is linked, the direct download URL, the download date, and the file's stated update date. Keep the downloaded copy with your review notes. That gives the team a clear record of which version was tested.

Do not describe an older stored copy as the hospital's current file. If the public file changes during the review, keep the versions separate and state which findings apply to each one.

2. Check the current CMS specifications

Use the CMS resources page to find the applicable templates, data dictionary, validator, and guidance. Record the specification and validator version used. An older guide can still explain background, but it should not replace the requirements that apply to the file under review.

Start here: CMS hospital price transparency resources

3. Separate technical results from data-quality questions

Run the available technical checks and save their output. For each issue, record the affected field, a reproducible example, and the relevant specification when one applies.

Keep data-quality questions separate from confirmed format errors. A surprising value, duplicate record, or missing-looking price needs context before it becomes a regulatory conclusion. Technical validation also should not be treated as proof that every published price is complete and accurate.

4. Assign and retest corrections

Give each issue an owner and a clear next step. Note whether the correction belongs in the hospital's source data, its file-generation process, or its publication workflow. After a correction, test the revised file and retain the before-and-after evidence.

When a vendor supplies the file, ask for the explanation and supporting correction rather than assuming a successful upload resolves the issue.

5. Keep a review record

A useful internal record includes the file version, checks performed, results, unresolved questions, correction owners, and retest dates. State what was outside the review's scope. Do not label the hospital compliant or noncompliant solely because one automated check passed or failed.

This workflow helps finance, revenue-cycle, compliance, and technical teams work from the same evidence. It does not guarantee a regulatory outcome or replace the applicable CMS rules.
